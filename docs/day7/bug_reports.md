## BUG-01. Падение программы при открытии записи с длинным текстом
- Серьёзность: Critical
- Статус: исправлен (ветка day7-dev-mahnev, коммит `fix(ui): ...`), проверен повторным прогоном TC-04 и TC-05
- Модуль: src/ui/details_view.py

Шаги воспроизведения:
1. Запустить `python -m src`, войти в хранилище.
2. Нажать «Добавить», в поле «Сервис» ввести строку из 3000 символов «S».
3. Пароль ввести любой, нажать «Сохранить».
4. Двойным кликом открыть запись.

Ожидаемо: открываются детали, название укорочено с пометкой «ещё N симв.».
Фактически: процесс завершается без окна. В консоли:
```
X Error of failed request:  BadValue (integer parameter out of range for operation)
  Major opcode of failed request:  53 (X_CreatePixmap)
  Value in failed request:  0x0
```

Дополнительно воспроизведено: то же падение при нажатии «Показать» на пароле из 3000 символов. Граница: при 1000 символах всё работает, при 3000 падает. Проверено для названия и для пароля.

Причина: надпись (Label) выводит строку целиком, её ширина превышает предел X-сервера, Tk завершает процесс.

Исправление: вывод в деталях ограничен 200 символами (`fit_for_display` в src/ui/validation.py), у надписей задан перенос. Полный пароль по-прежнему копируется кнопкой «Копировать пароль».

Окружение: Linux + X11. Поведение на Windows не проверялось. Возможно, там падения нет, но вывод длинного текста без ограничения всё равно неверен.

Скриншот: не получен, окно не успевает отрисоваться до падения. Текст ошибки приложен выше.

## BUG-02. Оценка надёжности «средний» для пароля из одного класса символов
- Серьёзность: Major
- Статус: исправлен (коммит `fix(core): ...`), проверен TC-07 и unit-тестом
- Модуль: src/core/strength.py

Шаги воспроизведения:
1. Открыть форму новой записи.
2. Ввести пароль `1234567890123456`.
3. Посмотреть строку «Надёжность».

Ожидаемо: «Надёжность: слабый».
Фактически: «Надёжность: средний». Так же для строки из 36 символов «a».

Причина: бонус за длину (12 и 16 символов) начислялся даже при одном классе символов, поэтому любая длинная строка из одного класса получала 3 балла, то есть «средний».

Исправление: бонус за длину начисляется только при двух и более классах символов. Старая версия не проходит 3 unit-теста на этот случай (см. test_run_report.md).

Скриншот: `docs/day6/screens/03_form_errors.png` показывает форму дня 6; для этого дефекта отдельного скриншота нет, строка индикатора текстовая.

## BUG-03. Длина генератора принимает «1_6»
- Серьёзность: Minor
- Статус: открыт, не исправлялся (косметика ввода, на безопасность не влияет)
- Модуль: src/ui/validation.py, parse_length

Шаги: в поле «длина» ввести `1_6`, нажать «Сгенерировать».
Ожидаемо: ошибка «Длина должна быть целым числом.»
Фактически: генерируется пароль длиной 16. Причина: `int()` в Python принимает подчёркивания между цифрами.
Окружение: см. выше. Скриншот не требуется.

## BUG-04. Нет ограничения длины полей формы
- Серьёзность: Minor
- Статус: открыт. Частично закрыт BUG-01: вывод укорочен, но сохранить запись на 100 000 символов можно
- Модуль: src/ui/entry_form.py, src/ui/validation.py

Шаги: в поле «Сервис» ввести 100 000 символов, сохранить.
Ожидаемо: сообщение о максимальной длине либо понятное ограничение.
Фактически: запись сохраняется без предупреждения, в списке название обрезается, в деталях укорочено.
Рекомендация: ограничить поля (например, 256 символов для текстовых полей). Это продуктовое решение: ТЗ лимит не задаёт, поэтому решает руководитель.
